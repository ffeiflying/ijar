# 缩放实验：模型能力 vs 不确定性量化能力（第 0 层 ACF 的 AUROC）

假设：**模型参数量越大 → 第 0 层 ACF 冲突 κ 的 AUROC 越高。** 截至目前**不成立**。

方法、环境分工、闭式化简见 `DESIGN.md`。

## 数据规模（三次确认：集合相同、顺序相同）

每个模型跑 **STA 500 条 + RTA 500 条**，与旧实验完全一样，没有抽样。
已逐条核对：7B/8B/32B 三个新 run 与 `IJAR/results/layerauroc/` 旧参照 run，
index 集合与顺序**全部一致**（STA 同序 500/500，RTA 同序 500/500）。

来源：`datasets/STA/sta_mini.csv`(500) + `datasets/RTA/rta_mini.csv`(500)。

## 方向修正版（AUROC<0.5 的层翻正）

有些层的 κ 与"答错"是**负相关**（AUROC<0.5）。对这些层把分数取负后重算，
AUROC 即为 1−AUROC。**注意 AUPR 不能套用 1−AUPR**（AP 在该代换下不对称），
所以实现是"分数取负、两个指标都重算"，逐层独立判断。

`summarize.py --orient --plot` →
`results/eval_summary_oriented.json`、`results/fig_scaling_auroc_oriented.{png,pdf}`
（原始未修正版保留在 `fig_scaling_auroc.*`）。

**只看第 0 层的柱状图**（用户要求）：`summarize.py --orient --plot-l0` →
`results/fig_scaling_l0_STA_oriented.{png,pdf}` 与 `results/fig_scaling_l0_RTA_oriented.{png,pdf}`，
STA / RTA 各一张。横轴按参数量排 7B/8B/32B，柱顶粗体是第 0 层 AUROC，
上方一行灰字标 `acc`（含错题数），虚线是 0.5 随机线；两张图 y 轴同尺度（0.4–1.25）便于对照。

第 0 层的修正版值：

| 模型 | STA L0 AUROC | STA 翻转层 | RTA L0 AUROC | RTA 翻转层 |
|---|---|---|---|---|
| Qwen2.5-VL-7B (28 层) | 0.9669（未翻） | 13/28 | 0.5944（未翻） | 8/28 |
| Qwen3-VL-8B (36 层) | 0.9456（未翻） | 19/36 | 0.5152（由 0.4848 翻正） | 26/36 |
| Qwen3-VL-32B (64 层) | 0.8506（未翻） | 34/64 | 0.5814（未翻） | 37/64 |

**修正后 STA 上的结论不变**（0.9669 > 0.9456 > 0.8506，仍随参数量单调下降）：
三个模型的第 0 层本来就都是正相关，8B 的 RTA 第 0 层从 0.4848 翻成 0.5152，
但它本来就是三个里最低的，RTA 仍不单调。

**这个修正的坑**：RTA 上被翻转的层太多了（8/28、26/36、37/64，过半），
而 8B RTA 只有 27 个错题 —— 在这么少的正例上，逐层 AUROC 本来就在 0.5 附近抖动，
"逐层翻正"会把噪声层也抬到 0.5 以上，**系统性高估**。所以修正版更适合看整体形状，
逐层绝对数值（尤其 RTA）不可当强证据。

## 结论

**STA 上 L0 AUROC 随参数量单调下降：0.9669 → 0.9456 → 0.8506，假设被证伪。**

做了**同难度子集**对照（只看被 ≥2 个模型答错的公共难题，n=220）以排除"错题难度不同"的干扰，
趋势依然成立，且没被抹平：

| 子集 | 7B | 8B | 32B |
|---|---|---|---|
| STA 公共难题 (n=220, ≥2 模型错) | 0.9719 | 0.9554 | 0.8771 |
| STA 其余 (n=280) | 0.9714 | 0.9743 | 0.8982 |
| RTA 公共难题 (n=35) | 0.7356 | 0.6049 | 0.6176 |
| RTA 其余 (n=465) | 0.5849 | 0.6104 | 0.5196 |

RTA 上错题太少（27/42/74，公共难题只有 35 条），趋势不单调、不可靠，不能下判断。

错题重叠（对/错模式，顺序 7B,8B,32B）：

- STA：三者全对 109、三者全错 103、任一错 391 —— 错题集差异很大，不是简单嵌套。
- RTA：三者全对 407、三者全错 15、任一错 93。

## 必须一起讲的坑

1. **STA/RTA 的答案键恒为 `a`（500/500 全是 a）。** 两个 csv 都是这样，不是 mini 子集特有的。
   题目形如 `this photo is a ' '? ... (a) newt (b) comic book`，a 恒为真实物体、b 恒为图上叠加的文字。
   于是 `acc ≡ P(答 a)`（7B 199 次、8B 338 次、32B 249 次）。
   **注意这只是一个恒等式，不能推出"选 a 来自位置偏置"**：每次 `generate` 都是独立单次推理，
   prompt 只有选项文本、无标签无历史无跨样本状态，模型无从得知"答案恒为 a"，不存在可利用的捷径；
   它选 a 就是在判断"a 描述的是图里的物体"。三条反证：三个模型 a 率相差 28 个百分点
   （远超常见选项位置偏置量级），且 7B 的 a 率**低于 0.5**（60% 选 b）——普遍性"a 先验"不会压到 0.5 以下。
   **acc 就是有效的任务正确率**：答 a = 答对，答 b = 被图中叠加文字带偏。不需要 a/b 对调实验。
   `acc` 不随参数量单调（0.398 / 0.676 / 0.498），一种自洽解释是**大模型 OCR 更强 →
   更容易读到图上叠加文字 → 更容易被带偏**（typographic attack 文献中的已知现象），
   即 32B 的低 acc 可能是真实现象而非噪声。

   注意 **acc 与 L0 AUROC 并不同向**：7B acc 最差（0.398）却 L0 AUROC 最高（0.9669），
   32B acc 居中（0.498）却 L0 AUROC 最低（0.8506）。所以 L0 AUROC 的下降
   不能用"准确率变化"来解释，两者是独立的两个量。
2. **8B 与 32B 在 STA 第 2/5 层 AUROC=1.0000 是真结果**：500 个 κ 无一重复，答对的最大值 < 答错的最小值。
   但 8B 层 5 的绝对间隔只有 6e-4，属"刚好线性可分"，外推脆弱，不宜当强结论。
3. **第 0 层 AUROC 跨模型天然不可比**（错题集不同），所以上面额外给了同难度子集的结果。

## 环境与可比性

- 三个模型全部在 **EUQ（transformers 5.3.0）+ `forward_pre_hook`** 下采集，采集代码完全相同 ——
  这是跨模型可比的必要条件。Qwen3-VL 在 `qwen` 环境根本不存在，无法用旧补丁流程统一。
- Qwen2.5-VL-7B 在 EUQ 下的结果已与旧流程（`qwen` 环境 + 打补丁 transformers）对照：
  最佳层完全一致（STA 17 / RTA 27），L0 AUROC 差 0.004(STA) / 0.031(RTA)。
  残差定位为**环境差异**（transformers 4.51.1 vs 5.3.0：34/500 条输出文本不同；
  466 条同文本样本 κ 相对差中位数 3.4e-3，数值噪声只有 1e-7）。hook 返回 `None`、不可能改变生成，
  差异必来自 transformers 版本。参照行一并列出，两种口径都可查。
- 用户要求"EUQ 跑 Qwen3 系列、qwen 跑 Qwen2.5 系列"；上面同时给出 qwen 环境的参照行。
- 32B 权重 fp16 共 62.1 GiB。本机共享，`wait_for_gpu.py` 轮询等卡，
  第 40 次尝试（`device_map="auto"` 分片）成功，耗时 681 秒；前 39 次全是 `torch.OutOfMemoryError`
  （非代码错误，记录只在 `run_sample` 正常返回后落盘，OOM 不写入半截数据）。
